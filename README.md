# TG Monetizator Parser

Локальный поиск и аудит публичных Telegram-каналов для партнёрства с личными экспертами.
Собственный проект: https://github.com/kevji1337/TG-Monetizator-parser
Рабочая папка владельца: `C:\programming\TG-Monetizator-parser`.

## Запуск на Windows

Нужны Python 3.12 и установленный Chrome для TGStat.

1. `setup_monetizer.bat` создаёт `.venv` и устанавливает зависимости. Панель при установке не запускается.
2. `run_monetizer.bat` запускает панель по явному действию пользователя. Для диагностики — `run_monetizer_dev.bat`, подробности в [Dev-инструкции](docs/DEV.md).
3. Адрес: http://localhost:8501, слушает только `127.0.0.1`.

На компьютере владельца ярлык `Запуск_Робота_TG.bat` на Рабочем столе направлен в эту папку.
`requirements.lock.txt` фиксирует проверенное окружение Python 3.12 / Windows; `requirements.txt` задаёт допустимые диапазоны.

## Возможности

- Основной поиск: 47 реальных тематик TGStat, без текстовых запросов. Тематики выбираются в панели.
- Редактируемые фильтры TGStat: язык, страна, тип, возраст, ERR/ER, состав аудитории, подписчики, охваты и ИЦ.
- Каталоги ChatGPT + Claude используются для оценки содержания и персонализации; генератор ключей убран из основного поиска.
- TGStat в одном Chrome; четыре потока публичного аудита `t.me/s`, общий лимит два запроса/с по умолчанию.
- Несколько именованных профилей TGStat с отдельными сессиями Chrome: ручной вход и автоматический переход к следующему профилю при явном ограничении доступа. Очередь и причины пропуска сохраняются. [Как добавить аккаунты](docs/TGSTAT_PROFILES.md).
- Штатное закрытие Chrome с ожиданием завершения процесса и восстановление браузерной сессии. В панели отдельно показаны последняя проверка входа и результат закрытия профиля; наличие папки само по себе не подтверждает авторизацию.
- Отдельный раздел «Профили TGStat»: список аккаунтов и карточка с входом, проверкой сессии, переименованием и удалением. Удалённые профили исключаются из поиска и доступны для восстановления; данные Chrome остаются локально.
- Цель — число предварительно подходящих каналов. Поиск продолжается после отсева; бюджет по умолчанию 10 × цель и 60 минут.
- Метрики, тип канала и соответствие направлению проверяются отдельно. Для зелёной метки нужны все три условия.
- Разбор текстов Telegram: до 15 последних публикаций по умолчанию, признаки личной практики, новостей, подборок и пересылок с цитатами. Распознанные нецелевые типы скрыты в таблице по умолчанию; фильтр можно снять. Фото, аудио и видео не распознаются.
- Цитаты, ссылки, предложения автора, явные цены и возможные контакты; пересылки и одинаковые тексты не считаются независимыми доказательствами практики.
- SQLite: история запусков, очередь восстановления, исключение прежних каналов, кэш 24 часа, заметки, статусы и ручные сообщения.
- Сохранённый запуск загружается без массового пересчёта. Устаревшие оценки отмечены отдельно; пересчёт по кнопке с прогрессом, а при продолжении поиска — в рабочем потоке до проверки цели.
- Локальный профиль отправителя; черновики по подтверждённым источникам и существующему предложению автора.
- Переносимый пакет ChatGPT/Claude на 10/20 каналов, проверяемый импорт JSON без API-ключей. Черновики без API строятся по локальным правилам; свободный разбор возможен во внешнем чате.
- Автоматический анализ Gemini через собственный OpenAI-совместимый прокси: максимум 5 запросов на запуск, кэш 24 часа, проверка цитат и отдельный черновик. Ключ вводится локально в панели. [Настройка Gemini API](docs/GEMINI_API.md).
- Адаптер для gemini-web2api-go 4.23.0: настоящий SSE, этапы ожидания/reasoning/ответа, отмена соединения и ограничение размера текста. В панели есть проверка версии и списка моделей без генерации. Фактическая модель не определяется по эху поля model.
- Поиск и публичный аудит продолжаются при сбое AI; кандидаты сохраняются в отдельную очередь. Её можно разобрать позже без Chrome. Ожидающие проверки каналы учитываются отдельно от подтверждённых экспертов.
- Очередь AI ранжируется по признакам личной практики. Есть сводка причин отсева, компактная карточка и план следующих контактов с историей и экспортом. [Работа с кандидатами](docs/CANDIDATE_WORKFLOW.md).
- Настройки панели и профиль отправителя автоматически сохраняются между запусками; API-ключ в Windows хранится зашифрованным через DPAPI. [Что запоминается](docs/UI_SETTINGS.md).
- Ручная разметка в панели, precision/recall и разбор ошибок отдельно от рабочих статусов.
- CSV UTF-8 BOM и Excel; скачивание учитывает фильтры.

```powershell
.\.venv\Scripts\python.exe robot_parser.py --categories 34 --count 30
.\.venv\Scripts\python.exe robot_parser.py --categories 53 --micro landscape_design --count 30
.\.venv\Scripts\python.exe robot_parser.py --channels @channel_one @channel_two --count 2
.\.venv\Scripts\python.exe robot_parser.py --resume
```

## Данные и устройство

`monetizer/` содержит самостоятельный публичный парсер; Telethon/Flask-приложения `src/` в этом репозитории нет.
Основные точки входа: `monetizer_app.py` (Streamlit), `robot_parser.py` (CLI).

Автоматические отчёты CSV/Excel сохраняются в `reports/` внутри проекта. База, checkpoint, профиль отправителя, логи и браузерный профиль находятся в `results/monetizer/`. Эти локальные данные исключены из Git.
Для резервирования работающей SQLite используйте SQLite backup API; при закрытом приложении можно копировать всю папку результатов.
21 канал и история прежней установки перенесены локально; GitHub содержит код и учебные примеры.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests_monetizer -v
```

Модульные проверки и Streamlit AppTest используют фикстуры и временные базы. Сервер, Chrome и реальная выдача TGStat не запускаются. Те же проверки настроены в GitHub Actions.
Реальное качество отбора требует ручной разметки, оно не выводится из числа пройденных тестов.
