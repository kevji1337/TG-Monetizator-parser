# Профили TGStat

Панель поддерживает до 20 локальных профилей, включая основной. Каждый профиль хранит отдельную сессию Chrome. Название профиля — ваш ярлык, а не проверенное имя аккаунта на TGStat.

## Добавление и вход

1. После обновления кода перезапустите панель. Она сама не запускается.
2. Выберите источник «TGStat — каталог тематик» и раскройте «Управление профилями TGStat».
3. Введите название и нажмите «Добавить профиль». Новый профиль будет выбран автоматически.
4. Нажмите «Открыть выбранный профиль для входа». В открывшемся Chrome войдите в нужный аккаунт TGStat и проверьте его имя на сайте. Пароли и коды вводятся на сайте, а не в панели.
5. Вернитесь в панель, нажмите «Проверить вход TGStat: …», затем «Закрыть Chrome штатно: …». Программа ждёт завершения Chrome и записи его профиля.
6. Снова откройте тот же профиль и проверьте вход. Так проверяется сохранение авторизации после закрытия. Затем закройте Chrome штатно и запускайте поиск.

Повторите эти действия для остальных аккаунтов. Выбор профиля автоматически сохраняется между открытиями панели. Название добавленного профиля можно изменить.

## Исправление сохранения сессий

Прежнее закрытие вызывало `undetected_chromedriver.quit()`: в установленной версии он завершает процессы драйвера и браузера. Также не было включено восстановление последней сессии, а кнопка закрытия не проверяла вход.

Теперь перед запуском включается `session.restore_on_startup=1` в выделенном профиле. Исходные настройки перед первым изменением сохраняются рядом в `Default/Preferences.before-session-restore-v1.json`. Пароли и cookie приложение не экспортирует и не меняет. Папки прежних профилей используются на месте.

Для закрытия применяется `Browser.close`, затем программа ждёт завершения именно своего процесса Chrome до 15 секунд. Только после завершения освобождается профиль. Если Chrome не закрылся, окно остаётся доступно в управлении, а автоматическое переключение откладывается. Принудительное завершение браузера для переключения не применяется.

Механизмы описаны в документации [восстановления сессии Chromium](https://chromium.googlesource.com/chromium/src/+/HEAD/components/policy/resources/templates/policy_definitions/Startup/RestoreOnStartup.yaml) и [Browser.close](https://chromedevtools.github.io/devtools-protocol/tot/Browser/#method-close).

Проверка входа смотрит признаки авторизации на странице TGStat: управление выходом или видимую кнопку входа. Если признаков недостаточно либо открыта проверка сайта, результат — «Вход не подтверждён». Наличие файлов Chrome и ответ `restricted` не считаются доказательством входа или его потери. Последняя проверка не гарантирует, что сервер не отозвал сессию позже.

После обновления перезапустите панель. Изменение настройки восстановления применяется при следующем открытии профиля. Уже удалённые или отозванные сессии эта правка не восстанавливает: если после повторного открытия TGStat просит вход, войдите заново и повторите закрытие/открытие.

## Поиск и продолжение

Новый поиск начинается с выбранного профиля. В «Управление профилями TGStat» есть настройка «Автоматически пропускать ограниченные профили»; в панели она включена по умолчанию и сохраняется. При явном ответе `restricted` или HTTP 401 робот закрывает текущий Chrome и открывает следующий сохранённый профиль. Порядок: выбранный, затем остальные по времени добавления. Заранее войдите в каждый нужный профиль.

Каждый профиль пробуется один раз за запуск. Ограниченные профили больше не используются в нём автоматически. Сетевые ошибки, HTTP 403/429 и CAPTCHA не запускают переключение; проверку сайта нужно пройти вручную в Chrome. Если переключение отключено, при `restricted` сохраняется прежнее ожидание ручного входа.

Под отчётом показан текущий профиль и доступен список пропусков с причинами. При смене профиля тематики начинаются с первой страницы: очередь каналов и результаты сохраняются, дубли отсеиваются по username. Смена профиля не обновляет лимиты времени, числа аудитов или AI-запросов.

Продолжение использует сохранённые список, текущий профиль и пропуски; выбор слева относится к следующему новому поиску. Новые профили, добавленные позже, попадут в следующий новый поиск. Старые запуски без списка профилей получают его при первом продолжении, начиная с прежнего основного профиля.

Если доступных профилей не осталось, новые страницы не запрашиваются; аудит уже найденных каналов может продолжаться. Частичный результат сохраняется. После восстановления доступа закройте диагностический Chrome и нажмите «Повторить пропущенные профили TGStat» под отчётом, затем «Продолжить сохранённый запуск». Сброс пропусков сам не запускает поиск. Новый поиск также пробует профили заново.

Вход в аккаунт сам по себе не гарантирует доступность поиска: действуют ограничения сайта и аккаунта. Отдельный AI-разбор сохранённых публикаций не использует Chrome.

Одновременно разрешён один Chrome этого проекта. Перед новым поиском или открытием другого профиля закройте оставленное окно кнопкой в управлении профилями или в Dev-диагностике. Если закрыли окно вручную, также нажмите кнопку в панели, чтобы освободить сохранённую сессию управления.

## Где хранятся данные

- Основной профиль использует прежнюю папку `results/monetizer/chrome_profile/`; перенос входа не требуется.
- Добавленные профили: `results/monetizer/chrome_profiles/<идентификатор>/`.
- Имена и идентификаторы: таблица `tgstat_profiles` в `results/monetizer/monetizer.sqlite3`.
- Последний результат проверки входа и закрытия: `session_state.json` внутри соответствующей папки профиля. В нём нет значений cookie или паролей.

Chrome хранит авторизацию в своём профиле. Эти папки содержат личные сессии; вся папка `results/` исключена из Git. Пароли и коды отдельными полями приложение не собирает. Консольный новый запуск по умолчанию использует основной профиль без автопереключения; продолжение сохраняет настройки запуска из checkpoint.

При внедрении проверены синтаксис и импорты. Реальный вход в аккаунты и поиск пользователь выполняет сам; браузер для проверки изменений не запускался.
