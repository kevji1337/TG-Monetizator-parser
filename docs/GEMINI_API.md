# Автоматический AI-аудит через gemini-web2api-go

## Подключение

В локальной панели раскройте **AI-аудит Gemini**:

- Включите «Анализировать посты через Gemini».
- Base URL: `https://gemini-api.osante.xyz/v1`.
- Model ID: `gemini-4-argon-thinking`.
- Вставьте Bearer token в поле **API-ключ прокси**. В Windows он автоматически сохраняется зашифрованным и восстанавливается после перезапуска.
- Начальный лимит: **5 запросов на один запуск**. Панель позволяет уменьшить его до одного.
- Общий таймаут по умолчанию 600 секунд, настройка 10–900 секунд. Он включает ожидание заголовков, reasoning и итогового ответа. Подключение ограничено отдельно пятью секундами. Если раньше были сохранены 120 секунд, значение сохраняется: увеличьте его в панели до 600 секунд для Argon Thinking с тремя upstream-попытками по 180 секунд.
- Лимит текста запроса по умолчанию 96 000 байт UTF-8, настройка 16 000–120 000 байт. Это размер текста, который web2api передаст модели, а не размер JSON на проводе или число токенов.

Ключ автоматически шифруется Windows DPAPI для текущего пользователя и записывается только в локальную SQLite как шифротекст. В обычные настройки, checkpoint, отчёты, Git и логи открытый ключ не записывается. Очистите поле, чтобы удалить сохранённый ключ; ключ из MONETIZER_AI_KEY при этом продолжает действовать, если эта переменная задана. На другой машине/под другим пользователем Windows ключ обычно потребуется ввести заново. В других ОС поле работает в текущей сессии, без сохранения открытого ключа на диск. Для консоли можно задать переменную окружения `MONETIZER_AI_KEY`; ключ не передаётся аргументом командной строки. Google SDK или OpenAI SDK не нужны. AI-транспорт использует HTTPX с отменой асинхронного запроса; публичный аудит Telegram по-прежнему использует requests.

Base URL, модель, таймаут, включение AI, лимит, фильтры и прочие параметры панели тоже сохраняются автоматически. Подробнее — [сохранение настроек](UI_SETTINGS.md). Ранее несохранённый ключ из старой версии после закрытия её процесса восстановить нельзя: в новой версии его нужно ввести один раз.

Это ваш прокси к веб-версии Gemini, не Google AI Studio. Программа отправляет POST `/v1/chat/completions` с `Authorization: Bearer ...`, полями `model`, `messages`, `stream: true`, `stream_options: {include_usage: true}`. Не передаются tools, response_format, temperature или max_tokens: управление форматом остаётся в промпте и локальной проверке. Используется Chat Completions, доступный в 4.23.0; Google native API появился в web2api только в 4.25.0.

## Совместимость с установленным web2api

26.10.2026 публичный GET `/` на указанном endpoint сообщил **4.23.0** и объявил `gemini-4-argon-thinking` среди моделей. Это проверка метаданных, без вызова генерации. Наличие модели в списке не доказывает действительность cookie, право аккаунта на Argon или оставшуюся квоту.

Клиент разобран по исходникам [тега v4.23.0, commit 64b2d2c](https://github.com/zexadev/gemini-web2api-go/tree/v4.23.0), в частности `server.go`, `sse.go`, `messages.go`, `client.go`, `context_file.go`. Различия новых выпусков сверены с [CHANGELOG](https://github.com/zexadev/gemini-web2api-go/blob/main/CHANGELOG.md):

- В **4.23.0** HTTP-клиенты прокси кэшируют таймаут при создании. Изменение upstream timeout в Settings может требовать перезапуска **самого web2api**. Это исправлено в **4.24.1**. Таймаут парсера и upstream timeout прокси — разные настройки.
- `strict_model` появился только в **4.24.0**. В 4.23.0 этого переключателя нет. После обновления прокси его можно включить вручную, чтобы обнаруженное переключение Google на более слабую модель приводило к ошибке вместо успешного ответа. Парсер настройки хоста не меняет.
- В Chat Completions поле `model` — запрошенное имя, а не подтверждённая фактическая модель. Реальная модель `UpstreamModel` пишется в Requests web2api. Клиент сохраняет `requested_model`, `response_model`, `actual_model: null` и не выдаёт эхо запроса за подтверждение Argon. Даже strict_model не гарантирует обнаружение подмены, если upstream не сообщил своё имя.

Кнопка **«Проверить web2api — без генерации»** выполняет только GET `/` и, при наличии ключа, GET `/v1/models`. Она показывает версию, результат авторизации и наличие Model ID. В GET `/` ключ не отправляется. Проверка также выполняется однократно перед первым сетевым AI-аудитом в рабочем потоке. При запуске панели, просмотре истории и пересчёте правил она автоматически не запускается. Отсутствие модели, неверный ключ или полная недоступность метаданных не расходуют POST-лимит.

## Как работает отбор

1. TGStat ищет по выбранной тематике. Аудитор получает описание и тексты публичной ленты Telegram.
2. Каналы с ошибкой загрузки или провалом числовых критериев не расходуют AI-запросы. Если независимых источников меньше двух, AI также пропускается.
3. Для остальных каналов отправляются тексты, даты, ссылки, метрики, выбранное направление и профиль отправителя. Это передача данных указанному вами прокси.
4. Модель классифицирует канал, сопоставляет с темой, выделяет предложения и готовит сообщение подходящему эксперту. Новости, агрегаторы, школы, бренды, магазины и вакансии не являются целевыми типами.
5. Ответ должен содержать правильные идентификатор и хэш запроса, допустимые значения и ID существующих фрагментов. Программа подставляет дословные цитаты и исходные ссылки. Для expert нужны два независимых источника без пересылок, включая публикацию. Ошибка доказательств классификации отклоняет оценку. Ошибки необязательных офферов/цен/контактов обрабатываются отдельно, как описано ниже.
6. Зелёная метка в AI-режиме требует подходящих метрик и проверенного ответа AI с expert + matched. AI не отменяет числовые критерии. Неизвестный тип/тема, отсутствие ответа и ошибки остаются на проверке.

В версии промпта `expert-audit-4` каждый источник разбивается на непрерывные дословные фрагменты до 700 символов. В запросе они передаются вместо дублирования полного текста. Модель выбирает `evidence: [{ref: "s01q001"}]`, а программа подставляет цитату, source_id, дату и ссылку из исходного снимка. Неизвестный ref, чужой канал или неверный хэш отклоняются. Несколько ref одного поста не становятся независимыми источниками. Выбор существующего фрагмента подтверждает происхождение текста, но не гарантирует правильность смыслового вывода модели.

Для оффера модель выбирает ref фрагмента, тип, предполагаемую принадлежность, `price_refs` и `booking_refs` из предложенных вариантов того же источника. Цена должна быть явно найдена локальным шаблоном; ссылки и контакты берутся из загруженного текста/HTML. Сам факт наличия ссылки не доказывает её назначение для записи — это отдельно оценивает модель и проверяет пользователь. В результат добавляются `prices_evidence` / `booking_methods_evidence`: значение, цитата, источник, дата и происхождение text/html_link. Отсутствие подходящей цены не означает бесплатность предложения. Для совместимости старый формат source_id/quote проверяется дословно; допускаются только различия пробелов. Слова, регистр и пунктуация автоматически не исправляются.

Классификация и её основные доказательства проверяются строго. Неподтверждённый оффер отбрасывается, неподтверждённая цена или способ записи удаляется из соответствующего списка. При этом корректная классификация сохраняется с `validation_warnings`. Предупреждения видны в карточке, полном экспорте и логе. Черновик сообщения при таких предупреждениях скрывается. Это не превращает отброшенные данные в факты и не отменяет требования к метрикам или двум независимым источникам. Пакетный импорт ChatGPT использует свою прежнюю строгую проверку и этим изменением не затрагивается.

В web2api есть ограничения длины по байтам, а не токенам. Перед отправкой считается UTF-8 размер всего промпта. Если он не помещается, сохраняются все ID публикаций и их дословные начала, с явной пометкой сокращения. Правила и профиль отправителя не обрезаются. Полные загруженные тексты остаются в базе; их хэш включён в ключ кэша. Модель проверяется только по переданной выборке. Если и после сокращения лимит превышен, POST не отправляется, канал остаётся на проверке с причиной. Такой отбор может пропустить предложение в конце длинного поста; это не означает отсутствие продукта.

Локальная классификация сохраняется отдельно в `classification`, её вердикт — в `local_verdict`. Ответ API — в `api_ai_review`; он не заменяет импортированную ранее отдельную оценку ChatGPT. Офферы AI и черновик можно посмотреть в карточке. Ручные рабочие статусы, заметки и сообщения автоматически не меняются. В разделе «Поиск» сообщение AI принимается отдельной кнопкой.

Наличие точной цитаты проверяется программой; корректность смыслового вывода модели всё равно требует выборочного контроля человеком. Программа анализирует тексты, а не фото, аудио или видео.

## Лимиты, кэш и остановка

- Один исходящий AI-запрос за раз в отдельном рабочем потоке. Поиск TGStat и публичные аудиты Telegram используют свой пул и продолжаются во время ожидания AI.
- Лимит до пяти учитывает **попытки POST**, включая таймауты, сетевые ошибки, 429 и ответы с неподтверждёнными цитатами. Автоматических повторов и HTTP-переадресаций нет.
- Счётчик сохраняется в SQLite **до отправки** и привязан к run_id. Перезапуск панели, продолжение поиска и кнопка аудита сохранённого канала не обнуляют его. Новый самостоятельный запуск получает свой лимит.
- Локально дополнительно учитываются 30 попыток в минуту и 80 в час для endpoint. Другие клиенты с тем же IP программа не видит; общий IP-лимит обеспечивает прокси.
- Успешный ответ кэшируется на 24 часа. Ключ кэша учитывает тексты, метрики, направление, профиль отправителя, endpoint, модель и версии правил. Повтор из кэша не расходует запрос. Изменившиеся данные не получают старую оценку.
- Лимит AI-запросов и временная недоступность прокси не останавливают публичный сбор. Он продолжается, пока число подтверждённых экспертов плюс кандидаты в очереди AI не достигнет цели, либо пока не сработают обычные лимиты времени/аудитов/выдачи. Если заполнена очередь, результат остаётся частичным: её каналы ещё не подтверждены AI. Публичные аудиты, уже находившиеся в работе, сохраняются; возможен небольшой запас сверх цели из-за этих аудитов.
- В AI-очередь идут каналы с подходящими метриками и минимум двумя независимыми текстовыми источниками, не определённые локально как нецелевой тип или чужая тема. Личный эксперт для них может ещё не быть установлен. Подтверждённые ответы AI с неизвестным типом остаются на ручной проверке, без автоматического повторного запроса тех же данных.
- Цель 30 AI-подтверждённых каналов обычно недостижима при пяти новых запросах. Лимит пять остаётся в силе; программа собирает дополнительную очередь для последующей проверки и отдельно показывает число AI-подтверждений. Ошибки не превращаются в зелёный статус по локальным правилам.
- 401/403/429/5xx, сетевой сбой, таймаут или ошибка доступа в ответе прокси приостанавливают дальнейшие сетевые AI-запросы этого поиска, сохраняя возможность использовать кэш. Публичный сбор продолжает работу. Проверьте аккаунт/cookie/лимиты и продолжите разбор очереди: доступен только остаток исходного лимита запуска.
- Кнопка остановки запрещает новые AI-запросы. Клиент отслеживает остановку и общий срок ожидания каждые 250 мс, включая период до заголовков/первого токена, отменяет локальную сетевую задачу и закрывает соединение. Удалённая генерация и повторы внутри web2api могут продолжиться; отмену на стороне Google клиент не гарантирует.
- При запуске панели, открытии истории и локальном пересчёте сетевые AI-запросы не отправляются.

## Уже найденные каналы

Откройте нужный запуск из истории, затем раздел «Поиск». Выберите канал и нажмите **AI-аудит этого канала по сохранённым постам**. Используются настройки AI из боковой панели и общий лимит выбранного запуска. Остальные строки помечаются как требующие пересчёта, если режим/настройки изменились. Кнопка «Пересчитать сохранённые оценки» пересчитывает правила и применяет уже сохранённые ответы AI, без новых сетевых запросов.

Для всей накопленной очереди нажмите **Разобрать только очередь AI — без TGStat**. При этом не открывается Chrome и не загружаются посты Telegram: обрабатываются сохранённые тексты. Лимиты запросов и общего времени выбранного запуска сохраняются; при исчерпании общего времени увеличьте «Лимит времени, минут» перед продолжением. Обычная кнопка «Продолжить сохранённый запуск» возобновляет и сбор, и AI-разбор. Кандидаты и очередь сохраняются в SQLite/checkpoint между перезапусками. Статус «Ожидают AI» и столбец экспорта «Ожидает AI-разбора» не означают подтверждённого эксперта.

Когда пять запросов израсходованы, доступна отдельная кнопка **«Новый AI-разбор сохранённых каналов — до 5 запросов»**. Только явное нажатие создаёт новый run_id, ссылку parent_run_id на прежний запуск и новый лимит до пяти POST. Используются уже загруженные посты; повторного поиска TGStat или загрузки Telegram нет. История и счётчик прежнего запуска сохраняются, CRM-заметки, статусы и утверждённые сообщения не сбрасываются. Продолжение такого AI-запуска также остаётся в режиме сохранённых текстов. Это не автоматический обход лимита: каждый новый раунд запускается пользователем отдельно. Кэш используется до новых POST; после исчерпания лимита каналы без свежего кэша остаются в очереди без массового сохранения одинаковых пропусков.

При недоступности публичного превью сначала обновите тексты. Чтобы проверить канал, скрытый фильтром нецелевых типов, снимите фильтр в таблице.

## Консоль

```powershell
.\.venv\Scripts\python.exe robot_parser.py --channels @channel_one --count 1 --ai
.\.venv\Scripts\python.exe robot_parser.py --resume --ai
.\.venv\Scripts\python.exe robot_parser.py --ai-queue
```

Ключ предварительно задайте в `MONETIZER_AI_KEY` локально, не публикуя его. Без `--ai` новый консольный поиск сохраняет прежний локальный режим. Продолжение сохраняет AI-режим выбранного запуска.

## Диагностика

В ходе работы показываются номер попытки, размер текста UTF-8, число источников и этап: ожидание начала ответа, получение reasoning, получение итогового текста. Во время ожидания обновление пишется примерно раз в 15 секунд; при смене этапа — раньше. Это индикатор активности, а не процент готовности. Текст reasoning не сохраняется, в JSON анализа попадает только `delta.content`. События usage с пустым choices учитываются отдельно. Поток применяется только после `finish_reason=stop` и `[DONE]`; SSE-ошибка при HTTP 200 или оборванный поток не превращаются в оценку канала. На случай буферизации шлюзом поддержан и обычный ответ JSON.

Ошибки различают отказ авторизации, `ip_slot_full`, `context_length_exceeded`, `model_downgraded` в новых версиях, серверный upstream timeout, локальный общий таймаут и нарушение формата ответа. Числовой Retry-After показывается, но повтор автоматически не отправляется. В логах нет тела ответа, reasoning, ключа или заголовков авторизации. ID завершённого ответа и длительность записываются до проверки цитат, даже если сама проверка отклонит JSON. В успешном разборе сохраняются версия прокси, время первого SSE-события, запрошенная/ответная модель и оценка usage от web2api. Оценка токенов приблизительная, не официальная тарификация Gemini.

В CSV/Excel справа добавлены статус и причина ошибки AI, исходный вердикт правил, полный разбор и черновик API. При включённом AI и пустом ключе новый поиск не запускается: заполните поле либо выключите AI.

Завершённый текстовый ответ сохраняется **до проверки JSON и доказательств** в локальной таблице SQLite `api_ai_responses`, вместе со снимком входных данных и безопасными метаданными транспорта. Ключи, HTTP-заголовки и SSE-reasoning туда не записываются. Неодобренный ответ хранится для диагностики, а не как подтверждённая оценка канала. В карточке есть **«Диагностика последнего ответа AI»**: просмотр, скачивание и исходное описание именно этого запроса. Скачиваемый JSON содержит ответ, публичные источники, тему и метаданные; отдельное поле профиля отправителя в него не включается, хотя текст модели может упоминать отправителя. Эти данные находятся в игнорируемой Git локальной SQLite; локальный снимок может включать введённый профиль отправителя. Старые отклонённые ответы, полученные до этой версии, не сохранялись и по одним сообщениям лога восстановлены быть не могут.

Проверка health/version не является проверкой генерации. Изменения адаптера не подтверждают качество ответа или работоспособность cookie без отдельного реального AI-аудита, запущенного пользователем.
