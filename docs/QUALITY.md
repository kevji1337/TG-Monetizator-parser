# Как измерить качество отбора

В панели откройте «База кандидатов, история и пакетный разбор» → «Качество отбора».

1. Выберите канал и изучите описание, посты, пересылки, выбранное направление и метрики.
2. Укажите тип, соответствие теме и итоговый предварительный отбор. Подходящий канал должен быть личным экспертом по нужной теме с подходящими метриками. При недостатке информации используйте unknown и «Нет».
3. Укажите, кто выполнил оценку, и основание. Нажмите «Сохранить оценку канала».
4. Повторите для 50–100 каналов из разных запросов, включая отсеянных кандидатов и неясные случаи. Не размечайте только зелёные строки: такой набор не покажет пропущенных подходящих экспертов.

Можно скачать JSON, заполнить только `label` и импортировать его с предварительной проверкой. `qualified` — логическое true/false, остальные значения:

| Поле | Значения |
| --- | --- |
| channel_type | expert, school, brand, news, job_board, aggregator, store, unknown |
| relevance | matched, mismatch, unknown |
| annotator | имя или обозначение проверяющего |
| note | основание решения по источникам |

Неразмеченные поля null пропускаются. Чужие каналы, дубли, устаревшие хеши, неполные и противоречивые метки отклоняются до записи. Метки связаны с username, текстами и направлением, отдельно от CRM и AI. Смена текстов или темы исключает прежнюю метку из текущего расчёта; она остаётся в базе как устаревшая.

Отчёт показывает TP/FP/FN/TN, precision (долю подходящих среди зелёных), recall (долю найденных среди подходящих по ручной оценке), точность типа/темы и список расхождений. Если знаменатель равен нулю, показатель null: это не нулевая точность. Синтетические модульные проверки не заменяют эту оценку.

При переносе проекта доступен 21 реальный канал. Ручные метки пока не заполнены, поэтому оценка точности на реальной выборке ещё не получена. Локальный шаблон подготовлен в `results/monetizer/evaluation/human_review.json` и не включается в Git.
